## Reproduction setup

- Mac simulator: iPhone 17 Pro, iOS 26.5, named `TouchTips QA`.
- Simulator ID: `03ECFC9E-7775-42FA-8BB1-BB8D67BEE34E`.
- DEBUG/simulator-only fixtures use a UUID-specific on-disk database under `Application Support/QATests`. Relaunch reuses the same database; separate tests do not share app records.
- Standard fixture: 30 dated people across two Charlottesville venues, plus one undocumented person. Stress fixture: 1,000 dated people plus one undocumented person.
- Real views, SQLite persistence, contact listener, MapKit, and notification center run. Fixture seeding itself does not create notification outbox entries.
- Contacts and When In Use location are granted to the disposable simulator before the suite. The permission-recovery test opens the real Settings app.

Run from a checkout containing the reviewed fixes and this harness:

```sh
nix develop -c just test
nix develop -c just test-ios 03ECFC9E-7775-42FA-8BB1-BB8D67BEE34E
```

Do not run against a personal simulator: notification tests create contacts, and the runner changes app permissions. Generated Xcode projects are not committed; `just gen` regenerates them from `project.yml`.

## Architecture assessment

Keep the existing local-first design: Contacts change history enters one serialized capture coordinator, SQLite owns resolution and the notification outbox, and the router handles notification destinations. The defects were chiefly lifecycle/state boundaries, not a need for a new event framework. Fixes make explicit selections distinct from defaults, give asynchronous work a generation or serialized owner, preserve durable retry state, and derive displayed summaries from live records.

The storage boundary is intentionally different: a failed persistent open is not an editable app. Recovery exposes the model only after opening succeeds. Background-task registration stays in the launch callback, separate from retryable model startup.

## Timing interpretation

Baseline cold map tap to accessible Map was 2.415 seconds; warm was 2.293 seconds. These include XCTest interaction/idle waits and are **not tile-render timings**. Screenshots at the first accessible frame and three seconds later are retained. These measurements do not justify a splash delay or establish a tile-loading bottleneck. No speculative prewarming is added.

## Release limits and follow-up

Simulator success is not a guarantee of background delivery. Neither paired physical device was available during this batch. Real-device checks remain necessary for NameDrop, contacts saved while TouchTips is suspended/terminated, Always location behavior, Focus/notification settings, low-power mode and battery impact.

Additional source-level risks not yet reproduced in this batch: a Contacts save followed by an app-database failure can leave a duplicate on retry; accent-insensitive search could be improved; continuous map clustering deserves profiling at large place counts. Do not describe these as measured performance defects or fixed behavior.

The unsigned iPhone Release build succeeds but emits the existing `BuildEnvironment.appStoreReceiptURL` deprecation warning. Whole-repository formatting lint also fails on existing code (baseline: 31 files; combined: 30 before the final local fixture formatting). No broad mechanical rewrite is included in these functional PRs; this is not a clean `just check`/lint sign-off.

## Test harness corrections

Baseline app failures were separated from automation mistakes. Populated note fields expose their value rather than their placeholder; no-results labels include the query; repeated place buttons require selecting the intended first match; staged onboarding nodes exist before they are visible; SwiftUI labels the location action `Location, Open Settings`.

With When In Use granted and no simulator location fix, the real listener test takes 8.48 seconds: a 0.3-second debounce precedes a bounded eight-second location lookup. Its original eight-second assertion was shorter than that valid path. The test now allows 15 seconds and still requires the actual Contacts notification/listener, with no manual capture tick after saving. The passing capture log records one new contact after an 8,010 ms tick.
